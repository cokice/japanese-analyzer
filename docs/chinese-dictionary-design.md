# 中文词典接入设计

状态：原始设计记录，2026-10-16 已由[多语言词典实现说明](./localized-dictionaries.md)更新。原设计分支：`feat/chinese-dictionary`，基线：`cf88024`。以下保留设计时的范围与估算；当前行为以实现说明为准。

首期让用户输入日语后，直接看到离线中文释义和现有英文原文，无需模型 Key。中文采用社区 Jitendex 中文版，明确标为「社区机器译文」。英文继续使用完整 JMdict；两个来源的义项分别呈现。中文维基词典作为后续独立来源扩展。

本阶段交付设计文档。后续实现按本文的步骤推进，设计阶段不修改应用接口、下载锁文件或生成数据。

## 产品范围

| 项目 | 首期行为 |
| --- | --- |
| 独立查词与句子内词典 | 使用相同的中英双语组件与数据层 |
| 内置查词 | 默认加载中文及英文，不新增模型请求 |
| 无中文匹配 | 英文照常显示，中文区提示暂无对应释义，保留主动 AI 翻译入口 |
| 外部词典 | 保持当前 HTTP v1 行为；成功结果不按数字 ID 自动关联内置中文 |
| 原形识别与语境释义 | 沿用现有用户触发逻辑，与词典原文分开 |
| 简繁中文界面 | 首期均展示源数据的简体中文，繁体界面标注「简体原文」；不把源数据称为繁体版 |
| 英文与韩文界面 | 英文义项优先展开，中文区可展开；按钮和状态覆盖四种界面语言 |
| 中文输入反查日语 | 留作后续功能，首期仍以日语词形及读音检索 |

中文源存在机器翻译错误及待核条目。来源标识在释义区持续可见，不能只放在设置或授权页。切换模型不重新生成中文源内容；用户主动翻译英文义项得到的结果仍单列为「当前模型译文」。

| 属性 | 值 |
| --- | --- |
| 上游英文数据日期 | 2026-08-11 |
| 中文发布与本轮校订日期 | 2026-09-27 |
| 下载大小 | 36,703,585 字节，约 36.7 MB；不代表最终应用增量 |
| SHA-256 | `9872fc32d05e3f7ea9b5b70a253610e49d99b6eef7db519b96faad1bbec2b678` |
| 格式 | Yomitan v3，218 个 term bank，释义为 structured content |
| 上游报告的有释义 JMdict ID | 211,107 |
| 与当前英文库的 ID 交集 | 211,103 / 218,863，约 96.45% |

ID 交集来自 2026-10-16 的包校验及本地英文库比对，只衡量关联能力，不代表中文完整度或翻译准确率。变体与重定向导致的一行一记录不能作为独立词条数量；非正序号不能直接当成 JMdict ID。

数据的来源与分发条件按上游 [LICENSE](https://github.com/greyindex/jitendex-yomitan-zh/blob/main/LICENSE)、[NOTICE](https://github.com/greyindex/jitendex-yomitan-zh/blob/main/NOTICE.md) 及包内 `index.json` 保留。转换说明需列明结构转换、合并重复变体、资源路径变更及未纳入的记录类别。

## 查询与数据关联

沿用英文索引作为检索入口。表面形式、辞书形、读音的排序与每页 20 条保持一致；拿到当前页英文词条后，以可信的内置 JMdict ID 读取中文补充。中文不参与英文排序和总数计算，因此增加中文不会让页面跳序或重复分页。

```mermaid
flowchart LR
  Q[日语词形或读音] --> E[现有英文索引与分页]
  E --> R[当前页英文词条]
  R --> C[按可信 JMdict ID 读取中文]
  C --> V[核对写法与读音]
  R --> U[双语词条展示]
  V --> U
```

关联规则：

1. 中文记录的正序号是候选 JMdict ID，仍须核对该记录的写法及读音与英文词条的允许组合。检索键采用统一的 NFKC 与假名规范化，展示文字保持源文。
2. 同一 ID 下，不同写法、读音及适用限制独立保留。合并内容完全相同的变体时合并其适用组合，不能只按词头去重。
3. 中文拥有自己的释义块 ID。英文 `entryId:senseIndex` 不用作中文义项地址，也不依据序号把两边义项拼成一行。
4. 缺少可信 ID、写法读音冲突、纯引用或重定向记录进入转换报告，不猜测词义。保留可用的正 ID 中文数据；暂不在英文检索结果中的 ID 不独立新增结果。
5. 英文升级时重算 ID、写法及读音关联报告。已失效的关联停止展示，不把旧中文自动挂到同形的新词条上。

## 类型与接口

保留 `DictionaryEntry.senses`、`DictionaryEntry.source` 以及 `DictionaryResult.entries/total/offset/hasMore` 的现有含义。新增可选中文补充信息，不迁移英文字符串字段，不影响旧 HTTP v1 服务。

建议在 `app/lib/dictionary.ts` 中新增以下概念；具体字段名在实现时保持一致：

| 类型或字段 | 内容 |
| --- | --- |
| `DictionaryLocalization` | `language`、`origin`、独立 `source`、`upstreamDate`、释义块列表 |
| `language` | 数据语言使用 `zh-Hans`；与界面 `zh-CN/zh-TW` 分开 |
| `origin` | 首期为 `community-machine-translation`，未来可扩展 `dictionary-original` |
| `LocalizedBlock` | 来源版本内的稳定 ID、适用写法读音组合、安全内容树 |
| `DictionaryEntry.localizations` | 可选补充列表；英文原文仍位于现有 `senses` |
| `DictionaryResult.localizationStatus` | 语言、来源版本及 `ready/unavailable` 状态；与外部服务 `fallback` 分开 |
| 每条中文匹配状态 | `matched/missing/incompatible`；`missing` 与整个中文数据不可用不能混用 |

`POST /api/dictionary/lookup` 的既有请求字段不变，内置成功结果增加中文补充。新客户端未收到补充字段时仍按旧协议展示原文，不能宣称已取得中文。外部成功结果首期不做内置补充；只有确实回退到内置英文时，才走内置中英查询。

外部服务声明的词条 ID 即使恰好是数字，也不视为可信 JMdict ID。首期忽略外部响应中未知的补充字段；以后若扩展协议，需同时扩展验证器、语言声明与规范 ID 约定。

客户端的词条去重键仍以英文来源、英文版本和词条 ID 为准；中文补充按中文来源、中文版本及块 ID 合并。辞书形补查和「更多词条」须保留已有中文内容，避免同一个英文词条被后到的响应覆盖成缺少补充的旧对象。

## 内容转换与展示安全

新建专用中文转换器，按 Yomitan v3 的结构读取 ZIP，不使用目前只读取单个 JSON 的英文 tar 转换器。只处理预期成员，校验 ZIP 路径、解压总量、成员大小和 JSON 层级；不执行包内脚本或应用上游 CSS。

把 structured content 转为应用拥有的安全内容树，保留列表、段落、注释、读音、表格、例句及其嵌套关系。渲染器使用 React 节点白名单；未知节点应给出转换诊断，不能静默丢掉释义。来源中的链接仅允许经过校验的 HTTP(S) 链接，内部查词链接转换为应用动作。

字形图片等含义相关资源需要保留。资源转换为 SHA-256 命名的本地文件；引用由安全内容树中的资源 ID 表示，不保留任意磁盘路径。新增只读的受会话认证保护的资源路由，验证哈希、清单成员及图片 MIME。禁止脚本化 SVG 等主动内容；可明确等价替换为文本的资源须记录转换规则。

转换报告必须输出最大块大小、最大词条响应大小、未知节点和资源依赖。先验证最复杂词条，再确定响应预算：普通查询按页包含中文；若真实样本超过预算，改为在展开时通过受认证的独立详情接口加载完整中文，而不截断释义冒充完整结果。这是实施步骤二完成前必须关闭的验证项。

## 双语界面

独立查词和句子详情使用同一个词条组件，基本顺序如下：

```text
食べる   たべる

中文释义                       社区机器译文
适用写法与读音
中文释义块、原有注释及例句
来源与版本                     更多内容

英文原文                       JMdict
英文义项、词性及适用限制
按需 AI 翻译英文义项
```

中文界面默认展开首个匹配中文块与前五个英文义项。其他读音、写法的中文块单独标明适用组合后展开；长块在节点边界折叠，并提供可键盘操作的「展开完整释义」。英语及韩语界面先展示英文，中文区默认折叠。

当前模型译文始终在它对应的英文义项下，不覆盖社区中文原文。源数据没有义项级对应关系时，也不把社区中文复制进当前模型的翻译缓存。缓存必须包含实际翻译输入来源及版本、英文义项 ID、目标语言与模型身份。

四种语言需要覆盖「社区机器译文」「简体原文」「暂无对应中文释义」「中文词典暂不可用」及版本日期说明。`lang` 属性按数据语言设置，去掉当前统一使用 `lang="en"` 的假设。保留现有浅深色、桌面侧栏和手机弹窗布局。

## 生成与打包

保留英文 `dictionary.lock.json` 及其 512 个分片。新增 `dictionary.zh.lock.json`，记录中文候选版本、完整资源 URL、SHA-256、上游日期、发布日期和转换器版本。设计稿中的候选值经实施时再次校验后才写入锁文件。

中文生成至 `data/dictionary/zh/`，按 JMdict ID 的 SHA-256 前两位生成 256 个只读 gzip 桶，另有版本清单、资源目录及关联报告。首期复用英文查询索引，中文不再建一套词形索引。中文清单不能沿用英文「必须 512 个文件」的校验条件。

`dictionary:prepare` 依次准备两套数据，有效缓存不重复下载。生成缓存的有效性包含源包摘要和转换器版本；变更英文锁文件时另重算关联报告。源包检查失败、未知的含义相关节点、缺失资源或分片校验错误会阻断构建。生成目录切换在所有中文文件验证后完成，清单最后提交。

英文与中文共用总计 32 MiB 的解压分片 LRU 预算，缓存键包括数据集、版本或摘要及分片名。不能简单各开一个 32 MiB 缓存后仍声称总预算未变。并发读同一分片合并，取消或失效请求不能覆盖新词条状态。

Next 文件追踪、Docker 和桌面复制范围包含中文分片、清单、资源及授权文件；新资源路由也配置文件追踪。资源不加入前端依赖图，浏览器只加载当前词条需要的资源。桌面运行阶段只读，内置查词不下载新数据。

## 版本更新与降级

英文继续执行既有 30 天快照发布门槛。中文源分开记录上游日期及中文发布日期，更新检查不得用校验日期替换数据日期。

本设计提出中文独立门槛：中文发布距构建不超过 90 天，上游英文数据距构建不超过 180 天。任一超过门槛，生产构建失败，更新检查报告需更新中文数据；开发准备仅提示日期。这是为社区更新节奏新增的产品选择，不改变英文的现有门槛。它不表示超过 30 天的中文仍经过了新的语义复核。

设置展示两个日期及距今时间；运行时达到门槛的已安装词典仍可查询，并显示数据较旧，不让桌面离线功能突然失效。每周与手动触发的工作流分别检查中英版本，生成带关联差异报告的待审 PR，不自动发布。

| 状态 | 行为 |
| --- | --- |
| 中文有匹配 | 展示中文、英文及各自来源 |
| 某词没有中文或版本间形式不兼容 | 保留英文；说明没有对应中文，提供主动翻译 |
| 运行时中文分片损坏或资源不可用 | 英文保持可用；中文显示不可用并可重试，禁止缓存为「无中文」 |
| 英文主数据不可用 | 沿用词典不可用错误，不伪装成未找到词条 |
| 外部服务失败 | 沿用回退原因与实际来源，同时报告内置中文状态 |
| 构建阶段中文缺失或损坏 | 阻断打包；不产出标称双语却只有英文的应用 |

统计只记录功能、成功失败、耗时、来源类型及是否命中中文；不记录查询文本、释义正文或密钥。

## 实施步骤与验收

| 步骤 | 主要改动 | 完成条件 |
| --- | --- | --- |
| 一 数据锁与转换样本 | 中文锁文件、专用 ZIP 转换器、固定测试样本、授权副本 | 校验正确；写法读音及节点结构保留；错误包和不支持内容能被定位 |
| 二 完整生成与关联 | 256 个中文桶、安全资源、关联报告、响应及缓存预算测量 | 对齐当前英文版本重现 ID 交集；完成最大词条预算选择；报告不兼容原因 |
| 三 服务端补充 | 类型、共享 LRU、查询补充与部分失败状态 | 英文排序分页不变；不同来源 ID 不串联；中文故障不阻塞英文；旧 HTTP v1 可用 |
| 四 双语界面 | 共享词条组件、安全内容树渲染、四语言与按需翻译 | 无模型 Key 显示中英；来源清楚；切词、辞书形补查及迟到响应均不串词 |
| 五 更新与打包 | 分别检查中英版本、文件追踪、Docker 和桌面资源路由 | 日期门槛边界测试通过；standalone、Docker 及桌面包能离线读取完整中文内容 |

关联测试包括「駅」「食べる」「橋」「箸」「はし」「生」；活用测试包括「食べられなかった」的用户触发原形识别，以及「答えにくい」没有独立词条时的真实提示。检查重复变体、混合读音、写法限制、版本不兼容、空结果、中文分片损坏和超大结构。

建立至少 300 项固定评估集，覆盖常用词、多义词、同形异音、假名词及专业词；分别报告中文命中率、适用组合匹配率、人工发现的误译及严重程度。ID 交集不作为这些指标的替代。严重误导性的误译须修正、排除或明确标记后再发布，修正表保留来源版本与上游反馈链接。

执行 `npm test`、`npm run lint`、`npx tsc --noEmit`、生产构建及桌面测试；扩展现有词典 smoke，覆盖真实中文命中、英文保留与本地字形资源。记录生成耗时、冷查询和重复查询耗时、解压缓存峰值、转换后数据体积及各平台包体积增量。

首期工作量估算为 4–6 人日，不含大规模人工释义校订。若复杂富文本或图片需要大量定制转换，步骤二应重新估算，而不是通过丢弃内容压缩工作量。
